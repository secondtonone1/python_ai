## 1. 项目背景

培训机构需要一套在线客服系统：访客在网页上咨询课程、开班时间、学费等问题。
目前的人工客服重复回答大量常见问题，效率低。本项目建设"AI 智能客服系统"：

- **本阶段**：AI 机器人基于知识库规则自动回答常见问题，答不上来自动转人工；
  客服人员通过工作台接管会话、查看运营统计、维护知识库。
- **后续阶段**：把规则引擎替换为真实大模型（LangChain/LangGraph），
  知识库检索升级为向量检索（RAG），本项目的分层架构保证这些升级只替换局部模块。

## 2. 术语定义

| 术语 | 说明 |
|---|---|
| 访客(Visitor) | 在网页上发起咨询的用户，无需注册 |
| 会话(Session) | 一次完整的咨询过程，包含多方消息 |
| AI 机器人(Bot) | 基于知识库规则自动应答的引擎 |
| 知识库(Knowledge) | 标准问题、关键词与标准答案的集合，机器人的数据源 |
| 人工接管(Takeover) | 客服将会话从机器人转为自己接待 |
| 追问澄清(Pending) | 机器人多个候选答案并列时，让访客按序号选择 |
| 满意度(Rating) | 访客对机器人回答的评价（满意/不满意） |

## 3. 用户角色

| 角色 | 接入方式 | 权限 |
|---|---|---|
| 访客 | 网页聊天页（无需登录） | 创建会话、对话、满意度评价 |
| AI 机器人 | 服务端引擎 | 自动应答知识库问题 |
| 客服人员 | 工作台（账号密码登录） | 接管/回复/关闭会话、知识库管理、统计报表 |

## 4. 功能需求

### FR-01 访客会话
- 访客打开聊天页即创建会话（会话级限流防刷，每 IP 每分钟最多创建 10 个）。
- 会话支持多轮对话，机器人回答具备上下文能力（追问澄清后按序号继续选择）。

### FR-02 AI 机器人自动应答（本阶段核心）
- 机器人基于知识库规则引擎应答：
  - 关键词匹配打分，唯一最高分 → 直接返回答案；
  - 多条并列最高分 → 追问澄清，让访客按序号选择（多轮上下文）；
  - 无命中 → 返回转人工话术，会话进入"等待人工"状态。
- 回答以**流式输出**（逐字推送），模拟真实大模型的 token 流效果。
- 命中知识条目时累计命中次数（运营统计）。
- 消息发送限流：每个会话每分钟最多 20 条（防刷）。

### FR-03 人工客服工作台
- 客服账号密码登录（密码 SHA256 加盐哈希存储）。
- 会话列表按状态查看：等待人工 / 人工接待中 / 已关闭。
- 人工接管：将会话状态从"等待人工"转为"人工接待中"。
- 客服回复实时推送到访客浏览器（WebSocket，无需访客刷新）。
- 关闭会话。

### FR-04 满意度评价
- 每条机器人回答下方有"满意/不满意"按钮，评价结果入库，供统计报表使用。

### FR-05 知识库管理
- 客服可查看、新增、修改、删除知识条目（分类/标准问题/关键词/答案/启用状态）。
- 修改实时生效（规则引擎每次应答都读取最新知识库）。

### FR-06 运营统计
- 报表指标：会话总量、会话状态分布、今日消息量、机器人回答数、
  知识库命中率、评价次数、平均满意度。

### FR-07 会话生命周期管理
- 会话状态机：机器人接待 → 等待人工 → 人工接待 → 已关闭；超时自动归档。
- 后台任务每 60 秒巡检一次，超过 30 分钟无活动的会话自动归档。

## 5. 非功能需求

| 类别 | 要求 | 落点 |
|---|---|---|
| 性能 | 单机支撑数百访客并发对话 | FastAPI(asyncio) + 线程池桥接阻塞 DB |
| 可靠性 | 数据库瞬时不可用时服务不崩溃 | 启动时连接池初始化失败仅告警，恢复后自动可用 |
| 安全性 | SQL 注入防护、密码哈希存储、前端 XSS 防护、接口限流 | 参数化 SQL、SHA256 加盐、textContent 渲染、滑动窗口限流 |
| 可维护性 | 配置与代码分离、统一日志、分层架构 | config.json、logging 轮转、五层结构 |
| 可扩展性 | AI 引擎可插拔，后续替换真实大模型零改动业务层 | BotEngine 抽象基类 |
| 可观测性 | 完整接口文档、统一错误码、运营统计 | /docs Swagger、统一 {code,message} 响应 |

## 6. 验收标准（课堂演示口径）

1. 访客打开聊天页，问"学费多少钱" → 机器人**逐字流式**输出知识库答案，可评价满意度。
2. 问"你们有哪些课程"与"课程有哪些"→ 命中并列时机器人给出**序号追问**，回复"1"继续回答。
3. 问知识库外的问题（如"今天天气"）→ 机器人提示转人工，会话出现在工作台"等待人工"列表。
4. 客服登录工作台 → 接管会话 → 回复 → 访客页面**实时收到**客服消息。
5. 连续快速发 21 条消息 → 第 21 条收到限流提示（429）。
6. 工作台统计页展示会话量、命中率、满意度数据；知识库新增条目后立即可被机器人使用。
7. 访问 /docs 可以看到全部接口文档并在线调试。

## 7. 后续阶段规划（本项目的演进路线）

| 阶段 | 升级内容 |
|---|---|
| Flask/FastAPI 精讲 | 本项目即教学载体：路由/依赖注入/Pydantic/WebSocket |
| Redis | 限流计数迁移 Redis（分布式限流）、热点知识缓存、在线状态 |
| MongoDB | 对话流水全量归档到 MongoDB（原始数据留痕） |
| Dify 低代码 | 对比教学：Dify 的编排能力 vs 本项目手写引擎 |
| 机器学习深度学习 | 用历史消息做意图分类，替换关键词匹配 |
| LangChain/LangGraph | 替换 RuleEngine 为 LLMEngine；知识库升级向量检索(RAG) |
